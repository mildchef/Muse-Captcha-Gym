# Corpus credits & provenance

## Type A corpus (v1) — 1,176 tiles

**Every image in the v1 corpus is synthetic.** No third-party photographs
were downloaded or used.

| Source | Items | Licence | Notes |

## Real-photo Type B transfer corpus (Stage 3) — 120 scenes, MS COCO 2017 val

| Source | Items | Licence | Notes |
|---|---|---|---|
| MS COCO 2017 validation images (`images.cocodataset.org/val2017`), annotations `instances_val2017.json` | 120 scenes + 120 derived mask PNGs | Annotations: **CC-BY 4.0** (COCO Consortium). Images: each keeps its own Flickr license — **only** COCO license ids 4 (Attribution, CC-BY 2.0; 79 images) and 5 (Attribution-ShareAlike, CC-BY-SA 2.0; 41 images) were admitted. Ids 7/8 (no-known-restrictions / US Gov) were admissible but did not occur; all NonCommercial (1, 2) and NoDerivs (3, 6) images were **excluded** (637 candidate images rejected on license alone) | Built by `tools/build_photo_corpus.js`. Per-image attribution (license name + URL, COCO id, original Flickr URL) is recorded in `corpus/typeB/manifest_photos.jsonl` — consult it before any use beyond this gym. Ground truth: COCO instance polygons rasterized mechanically (pixel-center rule); per-tile overlaps follow SPEC §4. Classes covered (COCO→gym): bicycle, car, motorcycle, bus, traffic light→traffic_light, fire hydrant→fire_hydrant. COCO `train`/`boat` deliberately unmapped (gym holdout classes, §4.6). Split is `eval` for every photo scene (SPEC §8.4 transfer set). |

SPEC §5.1 lists openly licensed photo sets (COCO / Open Images) as the
first-choice source. For v1 they were impractical at the required volume
(≥840 tiles with defensible per-tile labels), so the spec's route (2) —
synthetic scenes with programmatically exact ground truth — was used for
the whole Type A corpus. If real photos are added later, each item's
source, licence and attribution MUST be added to this file and to the
manifest before the item enters the pool.

## Type B corpus (v1.1) — 352 scenes + 352 masks

**Every Type B image is synthetic too**, generated by
`tools/build_corpus_typeb.js` with the same per-class painters as Type A.

| Source | Items | Licence | Notes |
|---|---|---|---|
| `synthetic` — rendered by `tools/build_corpus_typeb.js` (480×480 scenes; each object painted on its own per-class layer) | 352 scenes + 352 mask PNGs | Project-generated; no external licence applies | The mask is the pixel-exact visible-owner map computed after occlusion punch-out, so per-tile overlap fractions (SPEC §4.2) are exact by construction. Recorded per scene in `corpus/typeB/manifest.jsonl` as `source: "synthetic"`, `licence: "generated"`, `annotators: 0`, `kappa: null` (no human annotation pass — same position as Type A). 44 scenes are sliver-engineered: the primary object is placed so a *measured* fragment of 0.5–5% of a tile lands across a grid line (SPEC §5.4). Splits: train 241 / eval 65 / holdout_final 46; holdout classes (train, boat) are not painted in Type B (SPEC §4.6). |
